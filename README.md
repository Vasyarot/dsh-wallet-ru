# dsh-plugin-wallet-ru

Баланс DeepSeek, тариф и расход сеанса в доке композера:

```
Не пик 12 ч 45 мин   ·   Баланс: $0.83 · ¥12.50 · бонус $1.00   ·   Сессия: 12,3 тыс. ток · $0.04
                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^        ^^^^^^^^^^^^^^^^^^^^^^^^
                          клик → пополнить                        клик → траты за 7 дней
```

## Что показывает

| Элемент | Значение |
|---|---|
| Тариф | `Не пик` зелёным, `Пик` красным |
| Остаток | сколько осталось до смены тарифа (`12 ч 45 мин`, `48 мин`, `5 ч`) |
| Баланс | доллары всегда и первыми, подчёркнуты и кликабельны — ведут на страницу пополнения; **юани и бонусные баллы — только если их больше нуля** |
| Сессия | токены за сеанс и его стоимость, подчёркнуты и кликабельны |

Валюты приходят с платформы как `normal_wallets` и `bonus_wallets` (каждая пара
`{currency, balance}`). Хост отдаёт их целиком, клиент печатает USD, затем
недолларовые кошельки (`¥` для CNY) и бонусные баллы с пометкой «бонус». Всё
остальное — в подсказке при наведении, включая источник баланса (аккаунт или ключ).

Место в доке — `order: 0.5`: сразу после «ток/с» (`order: 0`) и **левее**
«Попадания в кэш» (`order: 1`).

Шрифт и отступы — от штатных плашек статистики: те же переменные темы
(`--dsh-content-font-size-secondary`, `--dsw-alias-label-tertiary`,
`--dsw-alias-separator-primary`), `padding: 1px 8px`, табличные цифры.

## Клики

- **Сумма баланса** — открывает пополнение **внутри приложения**, штатным окном
  просмотра платформы: оверлей на всё окно с полосой «‹ Назад · Пополнение
  баланса · Перезагрузить · В браузере», под полосой — нативная страница
  `platform.deepseek.com/top_up`. Автоматического перехода во внешний браузер
  нет — только по кнопке «В браузере».

  **Почему оверлей в `shell.overlay`, а не полоса под композером.** Окно
  платформы регистрируется в том же устойчивом хосте, куда штатный раздел
  «Аккаунт» кладёт свои страницы (`PlatformOverlay` из `ui-settings-account`).
  Раньше окно жило в доке композера: любая перерисовка дока могла снести
  нативную вьюху, и окно «открывалось», а рисовать было уже нечему. Оверлей
  ещё и сдвигает содержимое под заголовок окна Windows
  (`--dsh-windows-titlebar-height`), поэтому страница не залезает под системные
  кнопки, а его область отдаётся в main как `getBoundingClientRect()` и едет за
  окном через `ResizeObserver`.

  **Белая страница — это проверка CloudFront.** `platform.deepseek.com` закрыт
  AWS WAF: ответ — `202` с `x-amzn-waf-action: challenge`, то есть пустая
  страница на 2.5 КБ с проверочным скриптом. Скрипт грузится с
  `*.token.awswaf.com`, и на этом канале его TLS-соединение рвётся
  (`ERR_SSL_PROTOCOL_ERROR`), проверка не отрабатывает, авто-перезагрузки не
  происходит — остаётся белый экран. Вьюха при этом считает, что страница
  загрузилась, поэтому снаружи отличить её от настоящей нельзя.

  Измерено на этой машине (без CDP-подсказок, обычные открытия окна): **2 удачи
  из 4** — то есть примерно каждый второй заход оставляет мёртвую проверку.
  Повторный `open()` (оболочка перед каждым открытием чистит куки сессии, так
  что это всегда «холодный» заход) даёт независимую попытку и обычно
  срабатывает. Поэтому в полосе **всегда** есть «Перезагрузить»: один клик —
  новая попытка, обычно страница появляется с первого-второго раза.

  Отдельно: если `open()` падает с сетевой ошибкой (`ERR_SSL_PROTOCOL_ERROR`,
  `ERR_CONNECTION_RESET` и т. п.), плагин сам повторяет попытку до трёх раз с
  паузой 0.8–2.2 с и пишет об этом в области статуса. Слепой повтор после
  *успешного* открытия не делается: он с равной вероятностью выбросил бы уже
  загруженную страницу.

  Больше из плагина сделать нечего — вьюха и её сессия живут в main-процессе
  оболочки, доступа к её DOM у плагина нет.

  **Почему не боковая панель-браузер.** Вкладка `browser` из `ctx.sidebarRight`
  открывается и адрес показывает, но страница в ней остаётся пустой: у вкладки
  своя сессия браузера (свои куки, без входа в аккаунт DSH), и
  `platform.deepseek.com` не отдаёт ей документ. Поэтому вкладка не
  используется, а окно платформы — то, которое работает с уже выполненным
  входом.
- **Расход за сеанс** — открывает маленькое окно над чипом: траты по дням за
  последние 7 дней (дата, токены, деньги) и итог. Закрывается по Escape,
  клику мимо и повторному клику по кнопке.

## Цены и данные

- Токены сеанса — проекция `tokenUsage` от слота (`useProjection`):
  ввод без кэша + чтение кэша + запись кэша + вывод.
- Деньги — по текущему тарифу, доллары за миллион: ввод `$0.14`, кэш `$0.014`,
  вывод `$0.21` вне пика; в пик ×2. Запись в кэш считается по цене ввода.
- Недельная статистика — хост читает журналы сессий (`sessionPersistence`),
  складывает usage по датам и считает каждый запрос по тарифу своего времени.

## Баланс

Два источника, по порядку:

1. **Обычный вход в аккаунт** — `deepseekAccount.getBalance()`, ключ API не нужен.
2. **Ключ API** — `GET https://api.deepseek.com/user/balance` с `DEEPSEEK_API_KEY`
   из credentials или окружения.

Сумма берётся из долларового кошелька; если его нет — `$—`, причина в подсказке.

## Установка

```powershell
pnpm add "dsh-plugin-wallet-ru@link:D:\Project\DeepSeek Harness\plugins\dsh-wallet-ru"
```

и добавить `dsh-plugin-wallet-ru` в `dsh.profile.bundles` профиля.

## Файлы

- `index.js` — маршруты `GET /wallet-ru` и `GET /wallet-ru/usage?days=7`.
- `client.js` — чип и окно недельной статистики.
- `cordis.patch.yml` — строка `wallet-ru` для дерева профиля.
